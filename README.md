# GitHub 实时推送 · 智能推荐与搜索仪表盘

单文件 HTML 仪表盘。在原「资讯展示」版本上升级为**智能推送 + 实时搜索**双引擎：自动按你的能力画像推荐可用项目并给出可核对的推荐理由，同时支持直接在 GitHub 上检索项目/功能。

页面：`index.html`（双击即可打开，零依赖、零构建）

---

## 一、这次升级了什么

| 能力 | 升级前 | 升级后 |
|---|---|---|
| 内容来源 | 静态展示 5 个版块 | 同左，但数据改为**按你的技术栈方向定向抓取**的真实 GitHub 数据 |
| 推送 | 无 | 🎯 **为你智能推送**：按画像打分排序，每条给出 3 条正面理由 + 1 条风险提醒；支持换一批、已读去重、更新检测 |
| 搜索 | 无 | 🔍 **GitHub 实时搜索**：直连 GitHub 公开 API，最多 10 条，每条带推荐理由 + star 数；默认按「对你的推荐度」排序 |
| 排序 | 按时间倒序 | 资讯区仍按时间；推送区/搜索区新增**可解释的相关性排序** |
| 数据 | 示例假数据 | 真实 GitHub 数据（含 star/语言/topics/体积/归档状态） |

**保留未动**：Hero 统计区 → 粘性锚点导航 → 响应式卡片网格 → 页脚数据源说明的整体骨架、GitHub 风格双主题、全局连续编号、北京时间人话格式、回退机制。

## 二、文件结构

```
github-push-dashboard/
├── index.html                      # 成品页面（数据已内联注入）
├── data.json                       # 本次注入的数据快照
├── data/snapshot.json              # 最近一次「抓取成功」的快照（回退依据）
├── scripts/
│   ├── fetch_data.mjs              # 抓取：画像方向搜索 + 关注仓库 Releases + HN + arXiv
│   └── inject_data.mjs             # 注入：把 data.json 写进 index.html 的注入标记之间
├── test/verify.mjs                 # 自动化验收：144 项
└── .github/workflows/gh-daily-push.yml   # 定时抓取 → 注入 → 自检 → 提交
```

### 编号约定（三套独立，互不污染统计）

- **推送区**：`P1…Pn`（推荐位，不参与资讯总数）
- **搜索区**：`S1…S10`（即时查询结果，不参与资讯总数）
- **资讯区**：`1…N`（全局连续编号跨版块，页脚「共收录 N 条」按此统计）

> 若希望推送区并入资讯区全局编号，把 `index.html` 里的 `PUSH_PREFIX` 改成 `''` 即可。

## 三、快速开始

```bash
# 1. 抓取真实数据（匿名调用 GitHub 公开 API）
node scripts/fetch_data.mjs

# 2. 注入到页面
node scripts/inject_data.mjs

# 3. 验收自检
node test/verify.mjs
```

环境变量（都可选）：

| 变量 | 说明 |
|---|---|
| `GITHUB_TOKEN` | 有 token 时搜索限流从 10 次/分 提到 30 次/分（Actions 自带） |
| `MAX_DIRECTIONS` | 抓几个画像方向，默认 8；调小可加快首跑 |
| `DELAY_MS` | 搜索请求间隔，匿名建议 ≥7000，有 token 可 2000 |
| `STRICT_TLS` | 设 `1` 则禁用本机证书链失败时的降级重试 |

## 四、智能推送机制

### 画像（`USER_PROFILE`，写在页面里，可直接改）

8 个方向，每个方向带**权重、关键词、"为什么对口"说明**：

软件测试与质量保障(30) · AI Agent/RAG(30) · 大数据 Spark/Hadoop(26) · 数据分析与可视化(24) · 机器学习与计算机视觉(22) · Java 全栈与后端工程(20) · 跨境电商与爬虫运营(20) · 自动化与效率工具(14)

### 打分维度（`scoreRepo()`，9 个维度全部来自仓库真实字段）

| 优先级 | 维度 | 数据来源 | 分值 |
|---|---|---|---|
| 1 | 方向命中 | name/description/topics 命中关键词数 | 权重 + 命中数×5（最多取 2 个方向） |
| 2 | 技术栈语言 | `language` | 命中 +14 / 不命中 −6 |
| 3 | 上手门槛 | `size` | ≤5MB +6 / ≤50MB +3 / >200MB −6 |
| 4 | 维护活跃度 | `pushed_at` | ≤7天 +10 / ≤30天 +7 / ≤90天 +4 / >1年 −8 |
| 5 | 热度 | `stargazers_count` | 10万分档 +1~+12 |
| 6 | 生态采用度 | `forks_count` | ≥3000 +4 |
| 7 | 项目新旧 | `created_at` | 一年内 +4 |
| 8 | 归档 | `archived` | −60（一票否决） |
| 9 | 重复推送 | 本地已读记录 | −15 |

**关键词匹配用词边界前缀匹配**，避免 `script` 命中 `TypeScript`、`test` 命中 `latest` 这类假阳性，同时保留 `test` → `testing` 的词形变化。

### 理由怎么来的

每张推送卡展示 **3 条正面理由 + 1 条风险提醒**，全部由上面的维度直接生成，例如：

> ✓ 命中你的「AI Agent / RAG / LLM 应用」方向 · 与你的 LangChain 智能体项目（ReAct + RAG + Ollama）同一条技术线（匹配 3 个关键词：llm、agent、rag）
> ✓ 主语言 Python 已在你的技术栈内，可以直接读代码改代码
> ✓ 最近 2 天仍有提交，维护活跃，遇到问题能等到修复
> ! 仓库超过 539 MB，体量偏大，建议先只读文档与示例目录

**不编造**：任何未在数据中出现的仓库、数字、结论都不会出现在理由里。

### 持续推送

- 每次打开页面按当前候选池重新打分（localStorage 记住已读，避免重复推同一条）
- 「换一批」翻到下一批（记入已读，不会绕回来）
- 每 5 分钟检查同源 `data.json` 是否有更新，有则横幅提示「检测到更新数据（共 N 条）」+ 一键刷新
- 页脚「重置推送已读记录」可清空记忆重新推荐

## 五、搜索机制

- 直连 `https://api.github.com/search/repositories`（GitHub 公开接口，无需 Key）
- 单次取回 30 个候选池 → 本地重排 → **最多展示 10 条**
- 排序：**对你的推荐度**（默认）/ Star 数 / 最近更新，切换排序不重复请求
- 支持 GitHub 原生限定符直接透传：`language:python` `stars:>1000` `topic:llm` `pushed:>2026-08-01`；无限定符时自动补 `in:name,description,topics`
- 输入防抖 450ms、回车立即搜、Esc 清空、`/` 聚焦、快捷 chips 一键搜画像方向

**异常与降级（全部有明确提示，不静默失败）**

| 情况 | 表现 |
|---|---|
| 匿名限流 10 次/分用完 | 提示「已用完，约 X 分钟后恢复」+ 剩余额度；展示本地索引结果 |
| 422 语法错误 | 提示检查限定符写法 |
| 网络不可用 / 被拦截 | 自动切换为**本地索引结果**并明示来源 |
| 查询无结果 | 提示换个说法，页面不空白 |
| 快速连续搜索 | `AbortController` 取消上一次未完成请求，防竞态覆盖 |

**注**：搜索结果的描述为 GitHub 原始英文描述（截断展示，标注为原文），推荐理由为中文——不对原文做自动翻译，避免编造。

## 六、数据流与回退

```
fetch_data.mjs ──成功──▶ data/snapshot.json（覆盖）+ data.json（isFallback=false）
              └─失败/0条─▶ 不覆盖 snapshot；data.json 由旧快照复制并置 isFallback=true
                              └─ 连快照都没有 → 空状态页（含手动重跑入口）
inject_data.mjs ──▶ 写进 index.html 的 /* @dashboard-data:start */ … /* :end */ 之间
```

页面读到永远是一份有效数据；`isFallback=true` 或 `generatedAt` 不在北京当天时，Hero 显示回退提示条，正文照常渲染。

## 九、已知限制

1. **搜索必须联网**——这是「直接在 GitHub 上查找」的固有要求，因此本页不再满足原版的「零外部请求」。当前策略是：静态资源零外链（无 CDN/字体/图标/图片），唯一的网络请求是用户主动触发的 GitHub 搜索 + 每 5 分钟的更新检测；两者失败都自动降级，且**推送与浏览功能完全离线可用**。
2. 匿名访问 GitHub 搜索限流 10 次/分钟，快速连续搜索会触发提示。
3. arXiv 摘要为英文原文，按 60 字截断（在词边界断开）。
4. 本机若存在 TLS 拦截，`fetch` 对 `api.github.com` 会报 `UNABLE_TO_VERIFY_LEAF_SIGNATURE`；抓取脚本会降级为跳过证书校验重试并打印警告，`STRICT_TLS=1` 可关闭该降级。Actions 等正常环境不触发。
